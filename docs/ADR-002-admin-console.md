# ADR-002 — Admin console («برنامه مدیریت») as a web area

Status: accepted (2026-10-09). No new service, no new dependency; a PWA-installable web area under `app/admin/(console)/*`.

## Decisions
- **Access**: `app/admin/(console)/layout.tsx` gates on `isPlatformAdmin`; every server function in `server/admin/*` and every route under `app/api/v1/admin/*` repeats `requirePlatformAdmin`. Mutations call `assertSameOrigin`. The legacy ops page `app/admin/page.tsx` and `POST /api/v1/admin/orders/[id]/complete` are untouched.
- **Cross-tenant reads** use SECURITY DEFINER functions that raise `app.rls_system_read` for one statement (migration 0061, same pattern as 0031): `system_admin_revenue`, `system_admin_orders`, `system_admin_users`, plus a SELECT-only `system_read` policy on `wallets`. Money is returned in toman (IRR ÷ 10). Revenue («فروش») = orders in PAID/QUEUED/PROCESSING/PROVIDER_SUBMITTED/IN_PROGRESS/COMPLETED; top-ups vs direct = PAID `payments.purpose`.
- **Prices are append-only** (migration 0062): new price = inactive DRAFT row; approval closes the active row (`active=false, effective_to=now()`) and activates the draft in one transaction. Active rows with `approved_at IS NULL` are seeded prices not yet confirmed by the owner. Drafts have `pricing_rule_id NULL`, so the automatic repricing job never rewrites them.
- **Suspension** sets `users.status='SUSPENDED'`, revokes sessions, and `resolveSession` now refuses non-ACTIVE users (before this only the Google flow checked status).
- **Settings** live in `platform_settings` (sms.melipayamak, auth.google, payments.gateway, site.licenses) and `invoice_settings` / `support_*` tables. Secrets are AES-256-GCM (`SECRETS_MASTER_KEY`), write-only: the browser sees `{set,last4,source}` only. Credential changes call `enforceStepUpPolicy('SECURITY_SETTINGS_CHANGE')`, which is a no-op until that policy is activated (migration 0027) — activate it together with MFA. Audit rows record keys, never values.
- **Env fallbacks kept**: SMS and Google already prefer the panel value over env; licence links from the panel now override `LICENSE_*_URL` (`/licenses`, `/api/v1/app/trust`); invoice seller/VAT and support contacts were already DB-driven.

## 2026-10 overhaul (migrations 0064, 0066, 0067)
- **Pricing**: every package has its own price. `service_package_prices` (append-only, 0064) pins a package's total; unpinned packages are quantity × unit. Editing the base pack (1 month / 1,000) moves the unit price and pins every other package at today's price, so nothing is silently rewritten. Each save/bulk/undo is a row in `service_price_batches` (0066) with before/after state; undo is a new batch. Bulk % has a server preview. Orders/checkout charge `resolvePackageTotal`; customer catalog payloads carry `packagePrices` (the mobile package screen must read `packagePrices[q] ?? q × unitPriceToman`). Unit costs (`service_unit_costs`) drive margin and the low-margin warnings. Variants (`<base>--<variant>`) are grouped under their base service; the owner can add one (inactive draft price) and approve it like any price.
- **Orders**: cross-tenant list/search via `system_admin_order_search`, routing via `system_admin_order_workspace`, then all per-order work in the customer's tenant transaction. Status moves are limited to QUEUED/PROCESSING/IN_PROGRESS/FAILED along the state machine; delivery uses `completeManualOrder` (note + https proof link); refund/cancel call `server/payments/refund.ts` (idempotent, ledger-correct; Idempotency-Key required). Customers are notified by the existing `orders.status` trigger and an inbox note.
- **Support / users / wallet**: tickets via `system_admin_tickets` + `addStaffReply`; assignment in `support_tickets.assigned_to_user_id`. Manual wallet adjustments post one `ADMIN_ADJUSTMENT` ledger entry through the shared helpers (IRT → IRR, locked MAIN account, idempotent per key, debit never below zero, mandatory reason, 20M toman cap per operation, audit + customer notice).
- **Settings**: site switches (`site.switches`: maintenance blocks new orders/checkouts, closed signups block new accounts; enforced in `createOrder`, `createCheckout`, `createAccountWithWorkspace`), referral programme (`referral_settings`), loyalty ladder (`loyalty.tiers`, read through `getTierLadder()` in `server/loyalty/tier-ladder.ts`), billing/VAT, integrations.
- **Team & permissions (0067)**: owner = global `platform_admin` (unchanged, all permissions). Staff are rows in `staff_members` (+ `staff_invites` claimed by a verified email/phone) with permission keys from `lib/admin-permissions.ts`. Every `server/admin/*` function calls `requirePermission(user, key)`; `adminMutation`/`adminRead` and the direct routes call `requireAdminAccess`; section layouts render «دسترسی ندارید». Rules in `server/admin/team.ts`: grant only what you hold, act only below you in the tree, never on yourself or an owner (so the last owner cannot be removed here), every add/update/suspend/remove/invite is audited with granted/revoked keys. The legacy ops page and `/api/v1/pricing/rules`, `/api/v1/ai/catalog/sync`, `/api/v1/content/entities` stay owner-only.
- **Audit viewer** reads `system_admin_audit` with redaction of credential-like metadata keys.

## Not wired (needs engineering, documented not hidden)
- **Payment gateway**: the merchant id and gateway name are stored encrypted, but no real adapter exists (`REAL_GATEWAYS` in `server/payments/gateways.ts` is empty), so online card payment stays off until an adapter reads `payments.gateway` through `getPlatformSetting`. The UI says so.
- **Customer-side consumption**: the customer web/app must (a) use `packagePrices` for package totals (mobile PackageScreen), (b) read `services.hint` / `sort_order`, (c) read the ladder through `getTierLadder()` instead of `lib/tiers.ts`. Category on/off is `products.active` (a switch); categories hidden in `lib/catalog-ui.ts` (`HIDDEN_CATEGORIES`) cannot be shown from the admin without editing that file.
- `WALLET_ADJUST` has no row in `transaction_security_policies`, so wallet adjustments rely on permission + cap + audit (no step-up).
- Site texts and lucky wheel from the requirements memo are future sections.
