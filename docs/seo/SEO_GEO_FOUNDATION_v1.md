# SEO + GEO Foundation v1

## Purpose

The public web surface is designed from day one for conventional search engines and generative search/answer systems. GEO here means **Generative Engine Optimization**: making factual, useful, crawlable, well-structured content easy for AI-powered search systems to discover, understand, quote and attribute. It is not a guaranteed ranking mechanism.

Google's current documentation states that SEO best practices remain relevant to generative AI features, and its June 2026 update clarifies that `llms.txt` is not required for Google Search and does not itself improve or harm visibility. We therefore treat `llms.txt` as an optional machine-readable navigation aid, never as a ranking dependency.

## Public information architecture

- `/` — canonical brand/entity homepage
- `/services` — service catalog landing page
- `/services/[category]` — category hubs
- `/services/[category]/[slug]` — individual service pages
- `/ai` — AI hub
- `/ai/[slug]` — AI capability/product pages
- `/social` — social platform hub
- `/social/[channel]` — channel-specific pages
- `/automation` — automation hub
- `/automation/[slug]` — use cases/templates
- `/pricing` — plans, entitlements and usage model
- `/blog` — editorial hub
- `/blog/[slug]` — canonical articles
- `/faq` — user questions and answers
- `/about`, `/contact`, `/terms`, `/privacy`

Private application routes must remain excluded from public indexing: `/dashboard`, `/auth`, `/workspace`, `/api`.

## Technical SEO baseline

- Server-rendered semantic HTML for public pages.
- One intentional H1 per public page.
- Unique title and meta description per indexable URL.
- Canonical URL on every indexable page.
- `hreflang` only when a real translated page exists; never generate fake alternates.
- `robots.txt` and XML sitemap generated by Next.js metadata routes.
- Noindex for private/authenticated surfaces.
- Stable, human-readable slugs.
- Avoid parameter-generated duplicate indexable URLs.
- Breadcrumbs for deep content pages.
- Open Graph/Twitter metadata for share previews.
- Image dimensions, alt text and descriptive filenames.
- Fast server response, optimized images, minimal client JavaScript.
- Core Web Vitals monitored after real deployment.
- Structured data validated before launch.

## Structured data policy

Use JSON-LD where the entity/page type is genuinely represented:

- Organization + WebSite on the homepage.
- BreadcrumbList on deep public pages.
- Product/Offer only when the page actually represents an offerable product/service and price/availability are current.
- SoftwareApplication for the software product where applicable.
- Article/BlogPosting for editorial content.
- FAQPage only for actual FAQ content. Do not expect FAQ rich results in Google; the feature was removed from Search in 2026.
- Service where it accurately describes a service entity.

Never add schema only to obtain a rich result. Structured data must match visible page content.

## GEO / AI-search content principles

1. Put the direct answer/value proposition near the top of each page.
2. Define entities, products, services and terminology explicitly.
3. Use descriptive headings and question-shaped subheadings where useful.
4. Prefer factual tables, specifications, limitations and eligibility criteria over marketing-only prose.
5. Keep claims attributable and current.
6. State prices, units, currencies, regions and dates explicitly when relevant.
7. Keep canonical source pages stable and internally linked.
8. Create original, non-commodity content rather than mass-produced keyword pages.
9. Include first-party evidence, methodology and update dates where claims require them.
10. Make important facts available in HTML, not only inside client-rendered widgets or images.
11. Avoid doorway pages, keyword stuffing, fake reviews, hidden text and schema/content mismatch.
12. Maintain a machine-readable index (`llms.txt`) as an optional aid for systems that choose to consume it.

## Entity graph

The public site should maintain stable identifiers for:

- Organization
- Website
- Product/service
- Service category
- Article
- FAQ page
- Person/author when applicable
- Social profile when officially controlled

Use stable `@id` values and connect entities through `isPartOf`, `publisher`, `provider`, `about`, `mainEntity`, `breadcrumb`, and related properties where appropriate.

## Search measurement

Track:

- Search Console impressions/clicks/CTR.
- Index coverage and canonicalization.
- Queries and landing pages.
- Rich-result enhancement reports.
- AI feature / generative search performance where the platform exposes it.
- Referral traffic from AI systems when detectable.
- Brand/entity query visibility.
- Content freshness and decay.

Do not hard-code an assumed ranking position or an assumed AI citation rate into product KPIs.

## Launch checklist

- Set `NEXT_PUBLIC_SITE_URL` to the real canonical origin.
- Verify robots.txt and sitemap.xml on production.
- Register and verify Search Console.
- Submit sitemap.
- Inspect representative URLs.
- Validate JSON-LD with Google's supported testing workflow.
- Confirm private routes are not indexable.
- Confirm canonical URLs resolve to 200 pages.
- Confirm Persian/English mixed text is crawlable and readable.
- Test social previews.
- Run mobile performance checks.
